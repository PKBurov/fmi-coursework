## Какво показа анализът (запомни това!)

**Тренд 2022–2025 (най-важното):** задачите вече НЕ пипат живата система. Дават ти
**конфиг файл или изхода на реален инструмент** (ssacli, occ, /proc/acpi/wakeup,
Antlrfile, bakefile, service descriptors) + **нарочно мръсни данни** (счупени редове,
`--` placeholder-и, липсващ завършващ нов ред) и искат:
1. разпарсване с валидация ред по ред (счупен ред → предупреждение/пропускане, НЕ фатална грешка);
2. сравнение "желано срещу реално" състояние;
3. генериране/отпечатване на командата вместо реалното ѝ изпълнение.

**Изпитният стил на скрипт (късат точки за липса на това):**
```bash
#!/bin/bash
set -euo pipefail                              # почти всяко решение започва така
if [ "$#" -ne 2 ]; then
    echo "Usage: $0 <arg1> <arg2>" >&2         # грешките на stderr
    exit 1                                     # отделен exit код за ВСЯКА проверка: 1,2,3...
fi
[ -f "$1" ] || { echo "$1 не е файл" >&2; exit 2; }
[ -d "$2" ] || { echo "$2 не е директория" >&2; exit 3; }

while IFS= read -r line; do                    # каноничният цикъл по редове
    ...
done < <(find ...)                             # process substitution, не pipe (за да не губиш променливи)
```

**Идиомите, които покриват 90% от stream задачите:**
1. **Екстремум:** `sort -n -t'X' -kN,N | head -n1` (мин) / `| tail -n1` (макс), после `cut` за полето.
2. **Опаковай ключа отпред:** `find ... -printf "КЛЮЧ@ПЪТ\n" | sort -n | tail -n1 | cut -d'@' -f2-`
   (`%s` размер, `%n` бр. hard links, `%T@` mtime, `%i` inode, `%d` дълбочина, `%u` собственик, `%p` път, `%f` име).
3. **Два паса:** `grep "$( ...вътрешен pipeline, който смята ключа... )" файл | ...`
   — "намери X от същия Y като най-Z-тия запис".
4. **Броене на честоти:** `cut ... | sort | uniq -c | tr -s ' ' | sort -n -k1 | tail -n1` (мода)
   / `head -n1` (най-рядкото).
5. **Число без водещи нули:** `([1-9][0-9]*|0)` — падало се е ДВА пъти (2023).
6. **Декорирай-сортирай-декорирай:** залепи ключ отпред със `@`, `sort -t'@'`, махни го с `cut`.

Успокоение: в 16-те stream задачи `awk` НЕ се появява нито веднъж, `sed` — само
веднъж. Всичко се решава с `grep / cut / sort / uniq / tr / head / tail / wc / find`.

# НАСОКИ (по една подсказка; гледай само ако забиеш)

- **Зад. 0А:** `readlink` дава СУРОВАТА цел на връзката (както е записана);
  `realpath -m` я абсолютизира дори да не съществува; `realpath -m
  --relative-to="$(dirname "$link")" "$цел"` смята релативния път. "Вътре ли е":
  `case "$abs" in "$root"/*) ...`. Капанът: `ln -sf ново връзка` върху връзка
  към ДИРЕКТОРИЯ създава новата връзка ВЪТРЕ в нея — трябва `ln -sfn`!
- **Зад. 0Б:** shell-ът взима ПЪРВОТО съвпадение в PATH → сложи fake-commands
  НАЙ-ОТПРЕД: `PATH="$fakedir:$PATH"`. ALLOWED_DIR трябва да е `export`-ната,
  иначе детето bash не я вижда. Завърши с `exec bash -i`. В (а) сравнявай
  канонизирани пътища (`realpath`), не текстово.
- **Зад. 0В:** рекурсивна функция с `local`; текущата директория за резолвване
  е `dirname` на ОБРАБОТВАНИЯ файл, не на началния. За бонуса: пренасочи цялото
  разгъване към `mktemp` файл и го `cat`-ни само при успех; цикълът се лови със
  "стек" от realpath-ове в string променлива + проверка за членство.
- **Зад. 0Г:** JSON-like списъкът се разбива с `grep -oE '"[^"]*"'` (стойностите
  нямат кавички вътре — точно затова!); дръж аргументите в bash МАСИВ, не в
  string (иначе интервалите ги разцепват); "последното печели" = просто
  презаписвай променливата; финалът е `cd $workdir` + `exec env "${envs[@]}"

  вади елегантно с `rev | cut -d"'" -f2 | rev`; флаговете: `tr ' ' '\n' | sort -u | tr '\n' ' '`;
  краен слаш: `${dir%/}`.
- **Зад. 2:** първо махни коментарите със `sed 's/#.*$//'`; форматът е точно
  `^[a-z][a-z0-9_-]* (running|stopped)$` — вече "sshd    running" пада сам;
  реалното състояние вземи ВЕДНЪЖ в променлива, не викай svcctl в цикъла.
- **Зад. 3:** един пас `find -printf "%i@%s@%p\n"` + `sha1sum` → записи `hash@inode@size@path`
  в mktemp файл; група = `cut -f1 | sort | uniq -d`; "вече линкнати" = в групата
  `cut inode | sort -nu | wc -l` е 1. Внимавай: `while` в pipeline губи промените
  по променливите (subshell!) — акумулирай с `< <(...)` или брой преди цикъла.
- **Зад. 4:** числото: `grep -Eq "^(0|[1-9][0-9]*)$"`; MB→KB е `*1024`; най-големият
  процес: `ps -u $u -o pid=,rss= | sort -n -k2 | tail -n1`.
- **Зад. 5:** shell функция с `local`, която вика себе си; редът се намира с

- **С1:** вътрешният `$(...)` смята типа на най-далечната: `tail -n+2 | sort -rn -t';' -k3,3 | head -n1 | cut -d';' -f2`; отвън търси `";ТИП;"` (с точните `;`, да не уцелиш име).

- **С4:** филтрирай имената с `grep -E "/[A-Za-z0-9_]+_([1-9][0-9]*|0)\.log$"`, брой със `grep -o error | wc -l` (внимание: `-c` брои РЕДОВЕ, не появи!).

## Зад. 0А (make-movable.sh)

```bash
#!/bin/bash
set -euo pipefail
[ "$#" -eq 1 ] || { echo "Usage: $0 <dir>" >&2; exit 1; }
[ -d "$1" ] || { echo "$1 не е директория" >&2; exit 2; }

root=$(realpath "$1")

while IFS= read -r link; do
    target=$(readlink "$link")            # суровата цел, както е записана
    linkdir=$(dirname "$link")

    if [ "${target#/}" != "$target" ]; then          # започва с / → абсолютна
        abs=$(realpath -m "$target")
    else                                             # релативна → спрямо dir-а на връзката
        abs=$(realpath -m "$linkdir/$target")
    fi

    case "$abs" in
        "$root"/*|"$root")                           # вътре → релативна
            new=$(realpath -m --relative-to="$linkdir" "$abs") ;;
        *)                                           # извън → абсолютна
            new="$abs" ;;
    esac
    ln -sfn "$new" "$link"
done < <(find "$root" -type l)
```

Точките се вземат/губят на три места:
1. `realpath -m` — без `-m` счупена връзка (несъществуваща цел) гърми целия скрипт.
2. `--relative-to="$linkdir"` — релативният път е спрямо ДИРЕКТОРИЯТА НА ВРЪЗКАТА,
   не спрямо root (класическа грешка).
3. `ln -sfn` — без `-n`, ако старата връзка сочи към директория, "новата" се
   създава вътре в целта, вместо да замени връзката.

```bash
set -euo pipefail
[ "$#" -eq 1 ] || { echo "Usage: $0 <file>" >&2; exit 1; }

out=$(mktemp)
trap 'rm -f "$out"' EXIT
stack=""                                   # "стек" от вече отворени файлове

expand() {
    local file="$1" abs dir line
    [ -r "$file" ] || { echo "не може да се прочете: $file" >&2; exit 4; }
    abs=$(realpath "$file")                # ЗАДЪЛЖИТЕЛНО след -r проверката!
    case "$stack" in *"@${abs}@"*)
        echo "цикъл в include: $file" >&2; exit 3 ;;
    esac
    stack="${stack}@${abs}@"               # push
    dir=$(dirname "$abs")
    while IFS= read -r line || [ -n "$line" ]; do
        if [ "${line#\!include: }" != "$line" ]; then
            expand "$dir/${line#\!include: }"      # рекурсията, спрямо dir-а на ТОЗИ файл
        else
            printf '%s\n' "$line"
        fi
    done < "$abs"
    stack="${stack%@${abs}@}"              # pop
}

expand "$1" > "$out"                       # нищо не отива на stdout преди успех
cat "$out"
```

```bash
#!/bin/bash
set -euo pipefail
[ "$#" -eq 1 ] || { echo "Usage: $0 <optfile>" >&2; exit 1; }
[ -f "$1" ] || { echo "$1 не е файл" >&2; exit 2; }

cmd=""; workdir=""
args=(); envs=()

while IFS= read -r line || [ -n "$line" ]; do
    line="${line%%#*}"                                 # коментарите
    line="${line%"${line##*[![:space:]]}"}"            # trim отдясно
    [ -z "$line" ] && continue
    key="${line%% *}"
    val="${line#* }"
    case "$key" in
        CMD)     cmd="$val" ;;                          # последното печели само
        WORKDIR) workdir="$val" ;;                      # с презаписване
        ARGS)
            args=()
            while IFS= read -r item; do
                args+=("$item")
            done < <(grep -oE '"[^"]*"' <<<"$val" | sed 's/^"//; s/"$//') ;;
        ENV)
            envs=()
            while IFS= read -r item; do
                envs+=("$item")
            done < <(grep -oE '"[^"]*" *: *"[^"]*"' <<<"$val" \
                     | sed -E 's/^"([^"]*)" *: *"([^"]*)"$/\1=\2/') ;;
        *)       ;;                                     # непозната опция → игнор
    esac
done < "$1"

[ -n "$cmd" ] || { echo "липсва CMD" >&2; exit 3; }
[ -n "$workdir" ] && cd "$workdir"
exec env ${envs[@]+"${envs[@]}"} "$cmd" ${args[@]+"${args[@]}"}
```

✅ Тествано (21.08): аргумент с интервали пристига като ЕДИН аргумент, коментар
след CMD пада, последният CMD печели, непознатата опция се игнорира, ENV стига
до командата. (На Linux с bash ≥4.4 може `mapfile -t args < <(...)` вместо
while-цикъла и просто `"${envs[@]}"` на exec реда; конструкцията
`${envs[@]+"${envs[@]}"}` е защита за празен масив при стар bash + `set -u`.)

Точките: (1) стойности с ИНТЕРВАЛИ оцеляват само ако args/envs са bash МАСИВИ
и се подават с `"${arr[@]}"` — string променлива тук е автоматична загуба на
точки; (2) парсването на JSON-like формата е тривиално именно защото условието
гарантира "без кавички вътре" — `grep -oE '"[^"]*"'` вади всяка стойност;
(3) `env K=V ... команда` прилага променливите И търси командата с новия PATH —
затова примерът намира cowsay в /usr/games.

```bash
set -euo pipefail
[ "$#" -eq 1 ] || { echo "Usage: $0 <dir>" >&2; exit 1; }
[ -d "$1" ] || { echo "$1 не е директория" >&2; exit 2; }

    [ "$distinct" -le 1 ] && continue            # само hard links помежду си
    groups=$((groups + 1))

    kPath=$(echo "$keeper" | cut -d'@' -f4-)
    size=$(echo "$keeper" | cut -d'@' -f3)
    while IFS= read -r rec; do
        [ "$(echo "$rec" | cut -d'@' -f2)" = "$kInode" ] && continue
        path=$(echo "$rec" | cut -d'@' -f4-)
        rm "$path" && ln "$kPath" "$path"
        saved=$((saved + size))
```
